 5.2.3.2 Назначение уровня FDAL с учётом архитектуры системы
Как только FDAL назначен для функции верхнего уровня на основе класса отказного состояния
верхнего уровня, архитектура системных функций, участвующих в реализации данной функции
верхнего уровня, исследуется с целью определения уровней гарантии разработки этих системных
функций. Настоящий раздел описывает процесс определения FDAL для таких системных
функций.
В процессе распределения функции верхнего уровня на две или более независимых подфункции
(т.е. одна подфункция сама по себе не может вызвать опасность верхнего уровня) возможно
назначение FDAL для, по крайней мере, одной из подфункций ниже FDAL функции верхнего
уровня. Однако возможно и такое распределение функций, при котором FDAL, по крайней мере,
для одной из подфункций будет таким же высоким, как для верхнего уровня опасности. Несколько
различных случаев назначения FDAL обсуждаются в последующих подразделах.
Чтобы лучше понимать принципы назначения FDAL и IDAL, необходимо ознакомиться с
определениями «группа функциональных отказов» - Functional Failure Set (FFS), и «элементы
группы» - Members, а также «независимость».
Использование понятия «группа функциональных отказов» (FFS) с учетом архитектуры системы
обеспечивает систематичность подхода к назначению уровней гарантии разработки. Для
выявления всех групп функциональных отказов, приводящих к каждому из отказных состояний
верхнего уровня, а также элементов этих групп, используются методы оценки безопасности
системы. Группы функциональных отказов для конкретного отказного состояния могут быть
выявлены с помощью методов качественной оценки безопасности, таких как анализ дерева
отказов (P-4761, Приложение D) или диаграмма зависимостей (P-4761, Приложение E).
Концептуально, в интересах назначения FDAL (и впоследствии IDAL) группа функциональных
отказов эквивалентна минимальному сечению дерева отказов (как определено в Р-4761), элементы
которого представляют потенциальные ошибки разработки, а не отказы. FFS используется для
выявления комбинаций элементов, которые могут привести к отказному состоянию и для
назначения процессов соответствующего уровня строгости в интересах сдерживания последствий
потенциальных ошибок. Отказное состояние может иметь как единственную FFS, так и их
множество, каждое из которых может содержать один или множество элементов группы.
