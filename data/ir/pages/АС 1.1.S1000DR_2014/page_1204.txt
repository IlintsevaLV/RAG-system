1.1.5 Управление таблицей состояний
Для определения последовательности данных и их фильтрации по контексту система
должна обеспечивать функцию сбора и хранения данных о состоянии системы. Это
достигается за счет использования переменных состояния и выражений с такими
переменными.
Система поддерживает перечень переменных и их соответствующих значений. Такой
перечень называется таблицей состояний. Любые данные, которые необходимы для
проведения фильтрации, ветвления, организации циклов, или которые нужны для
перехода к внешнему приложению, должны определяться в виде переменной и
сохраняться в таблице состояний.
Система получает значения для переменных через диалоги пользователя,
интерфейсы внешних приложений или в виде заданных значений. Система
использует такие значения переменных для вычисления выражений. По результатам
вычисления выражения определяется, какие данные будут представлены
пользователю для просмотра.
2 Сведения о процессе
2.1 Основные правила схемы
Процессный модуль данных использует последовательности и конструкции
фильтрации для обеспечения непрерывного логического потока данных для
пользователя. Этот поток реализуется с помощью программного логического ядра.
Пользователь будет перемещаться по ряду элементов данных согласно
последовательности, предусмотренной разработчиком процессного модуля данных.
Пользователю могут быть заданы вопросы для упрощения ветвления if-then-else
(если-то-иначе) и фильтрации по применимости. Разработчик решает, что видит
пользователь и какой выбор ему предоставлен. Пользователь подтверждает
выполнение инструкции в элементе данных, а логическое ядро выбирает следующий
элемент данных для просмотра на основании сведений о состоянии. Основные
конструкции процессного модуля данных описаны в главах, указанных в Разд. 1.
