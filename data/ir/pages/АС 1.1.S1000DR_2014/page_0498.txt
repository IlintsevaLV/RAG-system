Примечание
Схемы уведомлений о передаче данных (DDN) и комментариев (COM) содержат
разметку изменений только внутри идентификационно-статусной части.
За исключением DDN и COM в идентификационно-статусной части каждого объекта
CSDB записываются причины изменений. Поскольку причины изменений включаются
во все пояснения изменений в данной главе, сначала поясняется сам предмет. См.
Разд. 2.2.
2 Использование разметки изменений
2.1 Общие правила
2.1.1 Ограничения использования
Использование разметки изменений ограничивается только показом технических
изменений. Разметку изменений следует использовать для указания изменений по
сравнению с предыдущим изданием модуля данных, а не между различными
inwork значениями атрибута . Любые изменения, указанные в предыдущем издании,
удаляются.
Примечание
Предыдущее издание модуля данных сохраняется в CSDB с разметкой
изменений текущего издания.
Для редакторских изменений разметка изменений не используется.
issueNumber issueInfo Модули данных со значением атрибута элемента < >,
001 issueType dmStatus равным " ", и значением атрибута элемента < >, равным
new " ", не должны использовать разметку изменений.
В сгенерированных TOC, LOT, LOF и ссылках не следует применять или указывать
изменения.
2.1.2 Запись причин изменения
Во всех элементах, содержащих разметку изменений, указывается причина
обновления. См. Разд. 2.2. Однако, графические и мультимедийные объекты также
могут содержать сведения о причине дополнения. См. Разд. 2.3.
2.1.3 Связь причин обновления
Подробные сведения об изменениях, внесенных в содержательную часть модуля
данных, записываются в идентификационно-статусной части. Связь изменения с
причиной изменения осуществляется с помощью атрибута
 reasonForUpdateRefIds id изменяемого элемента и атрибута элемента
reasonForUpdate < >.
При изменении содержимого элемента значение этого атрибута
reasonForUpdateRefIds устанавливается равным значению атрибута id
reasonForUpdate элемента < >.
