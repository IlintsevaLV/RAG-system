Описание
1 Общие сведения
В данной главе описывается логическое ядро. Логическое ядро - это компонент
программного обеспечения, исполняющий процессные модули данных (Спецификацию
см. в Глава 4.11 , требования см. в Глава 7.6.1 ). Оно реализует поведение, связанное
с элементами схемы процессного модуля данных. Основная задача логического ядра
– определить, какие данные отображать далее. Для этого логическое ядро должно
проходить по элементам процессного модуля данных, вести таблицу состояний,
отображать диалоги и вычислять выражения.
Процессный модуль данных содержит структуры интерактивной обработки,
позволяющие выстраивать последовательность других модулей данных или шагов на
основе статических или динамических данных о состоянии. Процессный модуль
данных применяется для реализации возможностей матрицы функциональности в
следующих категориях: (1) диагностика (в частичности, динамическая диагностика
или системное моделирование), (2) внешние процессы, где данные собираются в
ИЭТП и передаются во внешние процессы, или наоборот, и (3) навигация и
управление фильтрацией (отображение для пользователя только данных, которые
ему необходимы) и взаимодействие, управляемое диалогом. См. Глава 6.4 .
Установление последовательности на основе сведений о состоянии, наряду с
управлением статическими или динамическими данными о состоянии, необходимо
для обеспечения "интеллектуального" и интерактивного отображения данных. Данные
функции являются принципиальными для формирования последовательности
проверок, поиска и устранения неисправностей, где последующие проверки зачастую
основываются на результатах текущей проверки (динамические данные о состоянии)
или данных, вводимых с интерфейса Объекта (через интерфейс внешнего
приложения). Кроме того, такие функции позволяют настраивать отображение
сведений для пользователя в соответствии с конфигурацией Объекта или
определенным состоянием системы.
Процессный модуль данных содержит структуры для прохождения в установленном
порядке по шагам и модулям данных, а также по веткам операторов if-then-else
(если-то-иначе) и циклам. Процессный модуль данных также фильтрует шаги и
Model модули данных на основании значения переменных состояния, например, [
 Test passed равно "B" или равно TRUE], которые хранятся в таблице состояний.
italics (В этой главе имена переменных выделены курсивом ( ), выражения
приведены в квадратных скобках [ ]) Если необходимые значения переменных не
указаны в таблице состояний, процессный модуль данных собирает сведения для
заполнения таблицы состояний от пользователя или из других источников, затем эти
сведения используются для принятия решений по распределению на ветви и
фильтрации. При установлении последовательности модулей данных изменения
самого модуля данных не требуются, таким образом, модули данных можно
неоднократно использовать во многих последовательностях.
