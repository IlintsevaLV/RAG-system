3 Управление модулем данных каталога ACT β ИЭТП
Каталог ACT не связан σ конкретным набором модулей данных. Это означает, что
каждая ИЭТП по умолчанию должна проверить, реализован ли модуль данных
каталога ACT β данной CSDB.
Если модуль данных каталога ACT реализован η найден ИЭТП, то ИЭТП может
построить ссылки между разными модулями данных ACT.
Если модуль данных каталога ACT не реализован η не найден ИЭТП, то ИЭТП не
предпринимает никаких действий.
4 Кодирование модуля данных каталога ACT
Для модуля данных каталога ACT закреплен особый информационный код: 0Α3.
У одного интегратора может быть только один модуль данных каталога ACT.
Идентификатор модели должен соответствовать идентификатору модели,
определенному интегратором для основного Объекта, η ,например, можно
использовать SNS 00-00-00.
Пример кода для модуля данных каталога ACT для велосипеда:

5 Использование атрибутов применимости поставщика
Если интегратор желает использовать атрибуты применимости поставщика β своих
комментариях по применимости модулей данных, то он должен объявить
идентификатор для таких атрибутов применимости β своих собственных модулях
данных ACT η/или CCT.
Например, поставщик данных по летательному аппарату может выражать
применимость β своих модулях данных σ использованием модели двигателя. Β этом
случае необходимо создать атрибут объекта для модели двигателя β своем модуле
данных ACT.
Существует два способа определить такие атрибуты применимости поставщика:
Интегратор предоставляет собственное определение атрибута применимости 
(внутреннее определение).
Интегратор использует определение поставщика для этого атрибута 
применимости (внешнее определение).
