2.3 Применимость и секретность
2.3.1 Применимость
Термин «Применимость» используется для указания того, к какой конфигурации
изделия относится модуль данных. Область применимости модуля данных
указывается в идентификационно-статусной части (см. Глава 3.9.5.1 ), а конкретная
применимость для различных конфигураций указывается в содержательной части с
помощью ссылочной применимости. См. Глава 3.9.5.3 .
2.3.2 Секретность
Если имеется несколько заказчиков, то кому-либо из них может не требоваться
информация о конфигурациях Объекта, которые они не получают. Также возможны
случаи, когда один из заказчиков не хочет, чтобы другие заказчики знали о том, что
он получил определенную конфигурацию Объекта, и, соответственно, даже о том,
что он получил сопутствующие модули данных для этой конфигурации. В таких
случаях для фильтрации данных в S1000D можно использовать применимость.
2.4 Идентификация модуля данных
Модуль данных идентифицируется посредством параметров, указанных в его
идентификационно-статусной части. В некоторых случаях для однозначной
идентификации модуля данных в целом достаточно использовать только подгруппу
этих параметров. Наиболее используемая из этих подгрупп состоит из кода модуля
данных, но обычно для обеспечения уникальной идентификации добавляются номер
издания или рабочий номер, а также коды языка или страны.
В Глава 7.5.1 описывается способ именования файлов модулей данных с помощью
следующих параметров (с подпараметрами) для получения полностью уникальных
идентификаторов в сетевой среде:
dmCode код модуля данных, элемент < > с атрибутами 
language язык, элемент < > с атрибутами 
issueInfo номер издания, элемент < > с атрибутами 
2.5 Идентификация экземпляра модуля данных
2.5.1 Расширение кода модуля данных
При наличии нескольких экземпляров модуля данных они должны быть однозначно и
надлежащим образом идентифицированы.
Для того чтобы обеспечить уникальность идентификации, существует расширенная
схема идентификации, применяемая для экземпляров модуля данных. Данная схема
гарантирует назначение уникальных идентификаторов независимо от причин или
ситуаций, требующих расширенной идентификации.
В схему идентификации добавляется два атрибута, которые содержат
дополнительные параметры помимо указанных в Разд. 2.4.
