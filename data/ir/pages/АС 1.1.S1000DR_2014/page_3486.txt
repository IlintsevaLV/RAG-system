2.2.1.1 Компоненты комментария-утверждения
Комментарии-утверждения могут быть двух видов: вычисляемые и текстовые.
2.2.1.1.1 Вычисляемые комментарии-утверждения
Вычисляемые комментарии-утверждения содержат следующие вычисляемые
компоненты, используемые во время вычисления:
applicPropertyIdent атрибут , содержащий идентификатор атрибута 
объекта или условия для проверки, то есть тот же атрибут, который
assign используется в элементе < > модуля данных "Таблица перекрестных
ссылок на объекты" (PCT) и обеспечивает ссылку на:
 productAttribute id • принадлежащий элементу < > атрибут из модуля
данных "Таблица перекрестных ссылок по применимости" (ACT) или
cond id • принадлежащий элементу < > атрибут из модуля данных "Таблица
перекрестных ссылок по условиям" (CCT)
applicPropertyValues атрибут , содержащий значения и диапазоны для 
проверки
2.2.1.1.2 Текстовый комментарий-утверждение
Текстовый комментарий-утверждение не содержит вычисляемых компонентов.
2.2.1.2 Правила вычисления
Если любое из следующих правил не выполняется, результатом будет логическое
значение "true", и соответствующие технические данные будут считаться
приемлемыми для отображения. Если технические данные нельзя определить как
полностью неприемлемые, их считают приемлемыми.
1 Комментарий по применимости должен иметь вычисляемый вид.
2 Должен существовать модуль данных PCT, идентифицирующий экземпляры
объекта.
3 Конкретный экземпляр объекта из PCT должен быть идентифицирован.
4 Идентифицированный экземпляр объекта в модуле данных PCT должен иметь
assign applicPropertyIdent элемент < > со значением атрибута ,
applicPropertyIdent совпадающим со значением атрибута элемента
assert комментария по применимости < >.
applicPropertyValue 5 Значение атрибута из идентифицированного
assign элемента < > в модуле данных PCT проверяется относительно значений
applicPropertyValues и диапазонов в атрибуте комментария-утверждения .
Если значение комментария-утверждения не соответствует проверяемому типу
данных атрибута объекта или условия, результатом является логическое значение
"true". Это условие является ошибкой, которую необходимо обнаружить и исправить
до доставки данных.
Если значение экземпляра объекта согласуется со значением комментария-
утверждения или попадает в диапазон комментария-утверждения, результатом
является логическое значение "true".
