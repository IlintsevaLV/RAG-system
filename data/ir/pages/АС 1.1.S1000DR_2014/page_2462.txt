2.2.3 Определения проверок
Коды модулей данных должны иметь следующую структуру:
YY-Y-05- SS -00- NN A-000Y-A (17 символов)
до
YYYYYYYYYYYYYY-YYYY-Y05- SS -0000- NN AAA-000Y-A (37 символов)
где:
" SS " - это тип осмотра: 
• "40": Плановые проверки (например, предполетный осмотр). Пример см. на
Рис. 1.
• "50": Внеплановые проверки (например, осмотр после жесткой посадки)
• "60": Программа контрольного полета (облета) летательного аппарата
" NN " является порядковым номером для обозначения специальных проверок. 
Пример:
Код модуля данных, описывающего проверку после жесткой посадки, имеет 
следующую структуру: 1F-A-05-50-00-18A-000A-A
2.3 Ресурсы и сроки службы
Каждый модуль данных должен содержать перечень оборудования в указанной
системе, которое должно быть заменено работоспособным оборудованием по
завершении ряда циклов или истечении заданного промежутка времени.
Каждая строка данных формируется из определенных ниже элементов. 
Каждый элемент заполняется в соответствии с приведенным описанием. 
Каждому элементу может быть присвоено только одно значение. При наличии у 
элементов нескольких значений должно быть предусмотрено соответствующее
количество строк данных.
