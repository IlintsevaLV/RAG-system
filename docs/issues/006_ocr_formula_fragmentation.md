\# Issue 6: OCR разбивает формулы на куски, детектор их не собирает



\*\*Приоритет:\*\* 🟡 средний

\*\*Трудозатраты:\*\* 3–5 часов

\*\*Файлы:\*\* `ingestion/ocr\_rapid.py`, `ingestion/region\_detect.py`

\*\*Источник:\*\* \[docs/reports/2026-09-22\_page\_tests\_1954.md](../reports/2026-09-22\_page\_tests\_1954.md)



\## Проблема



На стр. 61 `\_1954.pdf` в верхней части страницы есть две настоящие формулы:



```

c\_N = 75N / (1/2 πR²ρ(ωR)³)

σ = kb / (πR)

```



Они \*\*не детектируются\*\* — отсутствуют в JSON и в v1 (до фиксов разработчика), и в v2 (после).



\## Данные



\### OCR возвращает формулы как разрозненные куски



RapidOCR на верхней части стр. 61 (`data/cache/\_1954\_p061\_top.png`, 2480×1042 px, DPI=300):



```

\[0.89] 75 N           ← числитель c\_N

\[1.00] с              ← обрывок "c\_N"

\[1.00] 1              ← часть "1/2"

\[0.92] πRp (ωR)3      ← знаменатель (ρ→p, ²→p)

\[1.00] 2              ← часть "1/2"

\[1.00] kb             ← числитель σ

\[0.94] πR             ← знаменатель σ

\[0.91] где T—тяга винта в кг;    ← продолжение текста

```



\*\*Формулы разрезаны на 5+ span'ов.\*\* Между ними вертикальные/горизонтальные разрывы.



\### Детектор не может собрать их в единый регион



`detect\_page\_regions` группирует span'ы по строкам с `y\_tol = max(8, page\_h\*0.012)`.

Для страницы A4 это ≈ 10 pt. Части дроби `1/2` (числитель `1`, знаменатель `2`) оказываются в \*\*разных строках\*\*. Плюс `πRp (ωR)3` — отдельный span.



\*\*Результат:\*\* ни один из кусков не выглядит как полная формула. `span\_math\_heuristic` не срабатывает.



\### Фильтр header/footer не при чём



```python

\# region\_detect.py, \~строка 351

body = \[

&#x20;   s for s in spans

&#x20;   if 40.0 < \_span\_center(s)\[1] < page\_h - 40.0 and s.text.strip()

]

```



Порог `40.0 < y` отсекает только логотип в самом верху (y ≈ 20–40 pt).

Формулы начинаются с y ≈ 100 pt — \*\*внутри body\*\*. Фильтр их не удаляет.



\## Причина



`span\_math\_heuristic` ожидает \*\*связный math-регион\*\* — один span или группу близких span'ов с math-символами. Для многоэтажных формул (дроби, степени) OCR даёт разрозненные куски, которые:



1\. Не пересекаются по y (разные строки).

2\. Не содержат полного math-контекста в каждом куске.

3\. Не собираются в один region.



\## Фикс



\### Вариант A (рекомендуется): `merge\_formula\_spans()`



Добавить пост-обработку OCR-вывода \*\*перед\*\* `detect\_page\_regions`:



```python

&#x20;   - если между span'ами < y\_tol и < x\_gap\_tol,

&#x20;     и хотя бы в одном есть math-маркер (`=`, `^`, `\\`, `π`, `ρ`, `ω`),

&#x20;     объединить в один span с общим bbox.

&#x20;   """

&#x20;   # ...

```



\*\*Пороги:\*\*

\- `y\_tol = 40 pt` — покрывает многоэтажные дроби.

\- `x\_gap\_tol = 80 pt` — покрывает пробелы между частями.



\### Вариант B: детектор формул по региону



Вместо поиска по span'ам — \*\*регион\*\*:

\- Если в y-полосе (например, `y=80..250`) есть ≥ 2 span'а с math-символами (`π`, `=`, `^`, `√`, `R`, `N`),

\- создать formula-регион \*\*на всю полосу\*\*,

\- применить UniMERNet к crop этой полосы.



\### Вариант C: универсальный — UniMERNet на \*\*каждый\*\* math-span



Если span содержит `=`, `^`, греческие буквы или ≥ 1 дробь-маркер — сразу отправить crop в UniMERNet. Пусть модель решает, что это.
