(`caption_source=ocr_caption`), плюс поиск `Фиг./Fig./Рис./Figure` в spans

## Как учитывать рисунки и графики в RAG

Сейчас figure почти мёртвый для поиска: пустой caption и (до #16) нет файла.
В индексе уже есть типы `figure` / `chart` / `drawing` — ими стоит пользоваться,
а не класть «картинку как есть» в тот же чанк, что абзац.

### Что индексировать (текст), что хранить (файл)

В векторный индекс кладётся **только текст**, который можно цитировать:

1. `figure_number` + подпись из книги (`Фиг. I.1. Одновинтовой вертолёт…`).
2. OCR-надписи на схеме (оси, `U, кВ`, позиции `А`, `Б`, размеры).
3. Короткий тип: `chart` / `scheme` / `photo` / `drawing` (эвристика
   `chart_candidate` уже есть; дальше — VLM или классификатор).
4. Ссылка на соседний абзац («как показано на фиг. I.1») — тот же `doc_id`+страница.

В метаданных чанка: `doc_id`, страница, `region_id`, `crop_path`, bbox.
Ответ RAG обязан уметь показать **цитату + превью**, не «галлюцинировать» график.

Сам PNG **не эмбеддить** как основной retrieval, пока нет нормального
мультимодального индекса. Картинка нужна для UI и для второго прохода
(пользователь открыл источник).

### Варианты по зрелости

**A. Подпись + OCR (сейчас, после #17).**  
Дёшево, работает на схемах и чертежах РДК. Слабо на фото и «голых» графиках
без текста. Это минимально полезный RAG: запрос «фиг. I.1 Белл» находит блок.

**B. Двухэтапный retrieval.**  
Сначала текстовый поиск по caption/OCR. Если score низкий, но в запросе
есть «график / зависимость / схема» — подмешать figure-чанки той же главы.
Не требует VLM.

**C. Описание VLM один раз при инжесте** (`ENABLE_VLM=true`).  
Одно предложение в индекс: «график зависимости cτ от µ, три кривые».
Хранить и OCR, и VLM (`caption_source`). VLM не заменяет номер фигуры из книги.

**D. Отдельный индекс картинок (CLIP / ColPali)** — позже.  
Имеет смысл, когда пользователь пришлёт скрин или спросит «такой же график,
как на стр. 40». Для нормативки с номерами фигур это не первый приоритет.

**E. Не класть в индекс полностраничные сканы и декоративные рамки.**  
Именно #18: иначе RAG «находит» всю страницу как рисунок.

### Графики (chart) отдельно от схем

- **График:** оси + легенда из OCR; в `content` поля `chart_x`, `chart_y`,
  `series` если удастся распарсить. Численные ряды с картинки не вытаскивать
  без отдельного пайплайна — легко соврать. В ответе: «см. фиг. N, ось …».
- **Схема / чертёж:** OCR меток + подпись. Это основной кейс РДК.
- **Фото:** только подпись из spans; OCR по пикселям почти бесполезен.

### Хранение файлов

- Путь как сейчас: `data/cache/figures/<doc_id>/pXXXX_figure_NN.png`
  (после #16 кириллица живая).
- В IR JSON — относительный `crop_path`, не копировать пиксели в JSON.
- Для продакшена: тот же ключ в object storage; в Qdrant/Chroma только URI.
- Не нормализовать `doc_id` в латиницу без нужды — ломает поиск папки руками.

### Что не делать

- Не эмбеддить пустой `caption=""` — мусор в выдаче.
- Не подменять формулу/таблицу figure (уже есть conflict-фильтры).
- Не обещать «прочитали значения с графика», пока нет отдельной верификации.

Рекомендация на ближайший цикл: **A + B + жёсткий #18**, VLM-описание (C)
включать точечно на документах, где OCR пустой. Мультимодальный индекс — после
того, как crop и подписи стабильны на rdk89 / usarmy / `_1954`.
