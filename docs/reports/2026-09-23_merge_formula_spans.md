## 1. Главная причина регрессии v5 (не только склейка)

У `_1954.pdf` **нет текстового слоя** (0 spans на всех страницах), все spans — из OCR.
v5 после этого ещё раз OCR-ил верхние 45% страницы и добавлял **сырые** OCR-строки
в обычную эвристику формул. Кадрированный OCR давал другую греческую кашу
(`Γλαβα` = «Глава», `ΣΟΔΕΡΚΑΗΝΕ` = «Содержание»), и она проходила как формулы.
В v5 весь мусор T8/T9/T10 шёл по пути одиночных span'ов, а не из склейки.

**Фикс:** дополнительный OCR верхней части работает только если spans пришли из
текстового слоя. Даже тогда в детектор идут только проверенные склейки, сырые OCR-строки
туда не попадают.

## 3. Что реализовано по ТЗ

- ≥ 3 math-маркера, math-ratio ≥ 30%.
- Стоп-слова, длинные слова (> 10 букв), OCR-каша из одиночных букв.
- Минимум 2 span'а в группе.
- Размер ≤ 30% ширины × 15% высоты страницы.
- Непустой crop ≥ 10 px.
- Фильтры TOC, двухколоночного текста, библиографии, header/footer и текстовых страниц — **до** склейки.
- TOC-проверка — ещё раз **после** склейки.
- Геометрия `can_merge` — пороги из ТЗ (4% / 15% / 2%).
- Уже готовые одиночные формулы (`m_κ = m_κp + m_κi`) склейка не трогает.

## 4. Где пришлось отойти от ТЗ и почему

Буквальные правила ТЗ отклоняли формулы из примеров самого ТЗ. Проверено на реальных
OCR-данных стр. 61:

| Правило ТЗ | Проблема | Что сделано |
|---|---|---|
| Маркеры = только `=+−×^_√…`, греческие, `\cmd` | `q = G/N` → 1 маркер, `M_K = ℏ/4` → 2 (ТЗ ждёт `True`) | `=` весит 2 (отношение двух частей), `/` между операндами = 1, `ℏ` (letterlike) = 1 |
| Стоп-слово `с` | OCR прочитал `c_N` как кириллическую `с` | однобуквенные стоп-слова считаются прозой только рядом с другим кириллическим словом |
| «> 50% одиночных букв» | цифры `1`, `2` из дроби `1/2` считались буквами → `c_N` отклонялась | считаются только буквенные одиночные токены |
| Пере-проверка `span_math_heuristic ≥ 0.5` | эвристика требует `=`, которое OCR потерял во фрагментах → отклоняет `c_N` | используется собственный score склейки (после строгого гейта) |
| `σ`: OCR «`πR`» | реальный OCR стр. 61 даёт `kb` над **`TR`** (π → T) — 0 маркеров в тексте | черта дроби проверяется **по пикселям**: короткая горизонтальная линия между числителем и знаменателем = 3 маркера (как `\frac`) |
| Фрагменты `c_N` и `σ` | зазор между `2` и `kb` всего 5 pt → сливались в одну группу | span не может быть одновременно знаменателем и числителем; вертикальная связь только через подтверждённую черту дроби |

Дополнительно (мусор, которого не было в ТЗ, но он появился на реальных данных):

- **Кириллица, прочитанная латинской/греческой головой:** `Myφτa` = «Муфта»,
  `Bepτoπera` = «Вертолета», `kak` = «как», `Πpι` = «при». Токены из ≥ 4 букв подряд
  отклоняются, а lookalike-стоп-слова транслитерируются и проверяются.
- **Только греческие буквы без оператора и без дроби** → не формула. Это главный
  источник каши на этом скане.
- **Нет ни одной латинской/греческой переменной** → не формула (подписи осей `0 -8 ---12`,
  номера страниц).
- **Линии таблиц и сетки графиков** похожи на черту дроби. Поэтому черта не должна
  выходить далеко за числитель/знаменатель, а склейки, пересекающие таблицу или рисунок,
  удаляются.
