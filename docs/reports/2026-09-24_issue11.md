# Issue 11 + греческая OCR-голова — отчёт

Дата: 2026-09-24. Задачи: [`docs/issues/011_semantic_filter_calibration.md`](../issues/011_semantic_filter_calibration.md)
и замечание про греческую OCR-голову (длинные греческие прогоны — мусор).

## 1. Что сделано

### A. `validate_latex` / битые скобки

Скобки больше не блокируют проверку навсегда. Перед `validate_latex` вызывается
`repair_latex`: схлопывает хвост `\! \! \! …` (обрыв `max_seq_len`), выкидывает
лишние `}`, закрывает незакрытые `{` и `\begin{...}`. Заметки:
`braces_repaired`, `spacing_collapsed`.

`{`/`}` в `\{` `\}` больше не считаются группами.

На `*_v6` у T3 было 3 региона с `unbalanced_braces` (p36 подписи кривых, p37
настоящая формула, обрезанная UniMERNet). После ремонта синтаксис проходит;
семантика по-прежнему решает, формула это или текст.

### B. Заголовки vs OCR-каша

Новый статус `ExtractStatus.CAPTION_OR_HEADER`. Если в регионе длинный буквенный
прогон / русские слова / проза в `text=`, **и** снаружи `\mathrm{...}` нет
операторов (`= + ^ _ \frac \sum \int \sqrt`), статус — `caption_or_header`.
В `content.text` кладётся OCR-текст спанов (LaTeX UniMERNet для заголовков
бесполезен). Такие блоки остаются в JSON для RAG как текст, не как формула.

Если операторы снаружи есть — остаётся `suspicious_semantic` (`long_letter_run` /
`prose_source_text`): это смесь формулы и текста.

### C. Ложные `figure_caption`

Зазор под рисунком 30 → 15 pt; регион должен начинаться **под** нижним краем
рисунка, а не внутри него. Правило срабатывает только если в LaTeX или OCR есть
текст (`_has_text_content`). Короткая формула рядом с рисунком (`\sqrt{\varphi+5}`)
остаётся `ok`.

### D. Греческая OCR-голова

Греческая голова нужна только для 1–2 символов подряд (`α`, `ωR`). Если она
читает целое русское слово греческими буквами (`ΚΗΑΓΑ`, `memnepamypy`), это
ошибка.

В `choose_ocr_candidate`:

- кириллическое чтение с уверенностью ≥ 0.5 и долей кириллицы ≥ 0.5 **не
  заменяется** похожим латинским/греческим (скелет lookalike + диграфы
  `Ы→LI`);
- греческая каша (`max_greek_run > 2`, смешанное слово `Kaτeropus`, одни
  «похожие» буквы ΑΒΕΗΜΝΟΡΤ) отбрасывается;
- одиночные отличительные греческие буквы **вшиваются** в кириллическую строку
  (`где ш — …` → `где ω — …`, `при а = 5°` → `при α = 5°`), русские слова
  (`для`, `п.4.3`) не трогаются;
- формулы без кириллического слова (`CπR2ρ(ωR)2`) остаются у греческой головы.

Непарные строки греческой головы в `_merge_multi_head_rows` с `is_garbled_greek`
отбрасываются.

## 2. Проверка

```powershell
$env:PYTHONIOENCODING='utf-8'
python scripts\check_ocr_heads.py --replay kt160g
python scripts\check_semantic_filter.py --ir "data/ir/page_tests/*_v6/_1954_regions.json"
```

| Скрипт | Результат |
|---|---|
| `check_ocr_heads` unit | 28/28 |
| replay KT-160G (11 стр.) | 1013 строк, 48 замен, **0** garbled Greek в выходе (было ~230 замен кириллицы на греческий мусор) |
| replay `_1954` page-tests | 2344 строки, 273 замены, **0** garbled Greek |
| `check_semantic_filter` unit | 25/25 + 3/3 repair |
| `*_v6` офлайн (статусы) | T3 18 ok / 9 sem; T4 8/3; T5 0/1; T6 4/3; T7–T10 = 0. Среди `ok` мусора нет. Часть sem станет `caption_or_header` в живом прогоне (зависит от `source_text`) |

На KT-160G p1 заголовок «АВИАЦИОННЫЙ РЕГИСТР…» больше не превращается в
`ΑΒΙΑ…`. На `_1954` p1 «АЭРОДИНАМИКА ВЕРТОЛЕТА» остаётся кириллицей.
Формулы p37 `75N = CNπR²ρ(ωR)²` и p40 `dM_κ` сохраняют греческие буквы.

## 3. Что проверить на рабочем ПК

Там UniMERNet и ночной прогон. Smoke из issue 11:

```powershell
python -m ingestion.run_regions "data\raw\КТ-160G-14G (Книга I)_compressed.pdf" `
  --pages 1,7,11,30,34,46,55,82,96,122 --out-dir data\ir\issue11_smoke_kt160g --enable-unimernet
```

Ожидание: заголовки `caption_or_header` (не `suspicious_semantic`); p034
`\sqrt{\varphi/1}` / `5Σ+` не `figure_caption`, если это короткая формула;
блоки с незакрытыми скобками — `ok` + `braces_repaired`, если это формулы.

Полный ночной прогон после фикса: цель ~70 ok / ~30 sem / ~15 susp / ~30 caption.
