# Кириллические двойники и гибридный поиск

**Дата:** 2026-10-01

После полного АС (4046 страниц, 15575 чанков) `probe` дал 95/100. Пять промахов — греческие буквы внутри русских слов и кодов S1000D: `β`→`в`, `η`→`и`, `σ`→`с`, `Σ`/`Δ` в `Σ1000Δ`. Длинный пункт из десятков частей вставал выше короткого, когда фраза вопроса лежала в обоих.

Формулы по-прежнему не индексируются отдельно. Ответ — текст чанка и место в документе. Генерации нет.

## Нормализация

`normalize_greek_lookalikes` в `core/text_norm.py` вызывается при нарезке чанка и при разборе запроса. Для каждой греческой буквы-двойника смотрится ближайший настоящий символ слева и справа. Пробел, цифра, пунктуация и другие двойники прозрачны. Одинокая латинская буква в скобках, как `(O)`, тоже не задаёт алфавит.

- Рядом только кириллица — кириллический двойник: `β соответствии σ` → `в соответствии с`.
- Рядом только латиница — латинский двойник: `ARP4754Α` → `ARP4754A`, `NASA’σ` → `NASA’s`.
- С обеих сторон разный алфавит — побеждает ближайший. У `η` и `β` латинского двойника нет: если хоть с одной стороны русское слово, буква всё равно становится кириллицей.
- Кластер из заглавных двойников и цифр через `-` `_` `/` всегда латиница, даже внутри русского абзаца: `Σ1000Δ-Α-08-02-0700-00Α-040Α-Α` → `S1000D-A-08-02-0700-00A-040A-A`.
- Два и больше двойников через точку — сокращение: `ε.γ.` → `e.g.`.
- Знак формулы (`=`, категория Sm) или настоящая греческая буква (`λ`) блокирует замену. `σ = μ + λ` и одинокая `α` остаются греческими.

К прежнему латинскому списку добавлены `Σ`→`S`, `Δ`→`D`, `Π`→`P`. Кириллический список: `β η σ ς ρ τ μ α ε ο κ`.

Старый OCR-путь `fix_homoglyphs_in_token` не изменён: токен с настоящей греческой буквой по-прежнему не переписывается.

## Короткий чанк

Если фраза запроса целиком есть в тексте, сортировка ставит выше более короткий чанк. Точное совпадение номера пункта по-прежнему даёт бонус +12 в лексическом поиске.

## Гибридный поиск

Режим запроса: `lexical` (по умолчанию), `dense`, `hybrid`. Векторы, если они уже лежат в индексе, сами режим не переключают.

Плотный индекс: `data/cache/text_index/dense.npy` и `dense_ids.json`. Модель `intfloat/multilingual-e5-small` из настроек, префиксы `passage: ` и `query: `, батч 32, только CPU. Ключ кэша — sha256 текста чанка. Неизменившийся чанк повторно не считается. Старый `vectors.json` при записи удаляется. Веса модели в git не кладутся.

Если `sentence-transformers` нет или модель не скачалась, `build --dense` пишет в журнал `dense skipped` и всё равно сохраняет лексический индекс. Код выхода 0.

Смешение — reciprocal rank fusion по первым 50 кандидатам каждого списка:

`score = w_bm25 / (k + rank_bm25) + w_dense / (k + rank_dense)`

`k = 60`, оба веса `1.0`, задаются `--w-bm25`, `--w-dense`, `--rrf-k`. К сумме добавляется бонус номера пункта, делённый на 12, чтобы точный пункт оставался выше ближайшего по вектору соседа. При равном счёте выше чанк с лучшим лексическим рангом. `hybrid` без векторов откатывается к BM25. `dense` без векторов завершается с кодом 2.

## Оценка

`python -m retrieval eval --gold data/ir/gold/retrieval_v1.json` считает recall@1, recall@3, recall@5 и MRR. Элемент эталона: `query`, `doc_id`, по желанию `clause_id` и `page`. Файл ещё не заведён: команда пишет, что golden нет, и указывает на `probe`.

`probe` по-прежнему берёт предложение из чанка и проверяет документ, пункт и страницу в top-5. Это самопроверка дословного текста, не перефраза.

## Проверка

`python -m retrieval check` проходит на синтетике: кириллическая строка с `η β σ`, код `Σ1000Δ`, формула сохранена, короткий пункт обгоняет длинный повтор, гибрид на искусственных векторах находит «требования к прочности гидросистем», лексический режим эту фразу не находит, повторная сборка того же чанка не вызывает энкодер.

Модель на этой машине не ставилась. Повторный `probe` на 15575 чанках — на рабочем ПК после `git pull` и `python -m retrieval build`. Ожидание лексического прогона: 100/100.

## Как прогнать

```powershell
python -X utf8 -m retrieval check
python -X utf8 -m retrieval build
python -X utf8 -m retrieval probe
python -X utf8 -m retrieval query "ARP4754A requirement validation issues"
python -X utf8 -m retrieval build --dense
python -X utf8 -m retrieval query "требования к прочности гидросистем" --mode hybrid
python -X utf8 -m retrieval eval --gold data/ir/gold/retrieval_v1.json
```

Для `--dense` нужен пакет `sentence-transformers` и доступ к весам `intfloat/multilingual-e5-small`. Индекс в `data/cache/text_index`, в git не входит.
