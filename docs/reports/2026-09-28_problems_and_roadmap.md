### Категория 1: Figure detection (рисунки)

#### Issue 20: Figure detector fails on scans

**Статус:** частично решён через Docling.

**Что работает:**
- `_1954` (русский скан): P=0.90, R=0.95, IoU=0.84 (цель P≥0.7 достигнута).

**Что не работает:**

- 10 ложных срабатываний на 12 страницах golden.
- FP на титульных страницах (логотипы FAA).
- Составные фигуры разбиваются на панели (Fig. 1.1 → 3 объекта).
- 2 unit-теста красные (`unexpected docling hits`, `pdf leaked`).

**Нужны фиксы:**
1. Фильтр логотипов: `if w < 100 and h < 100 and near_page_corner → reject`.
2. Merge близких панелей: `if two Pictures overlap by x > 50% and y distance < 30 pt → merge`.
3. Починить 2 unit-теста.

#### Issue 17: Caption fallback создаёт лишние figures

На `_1954 p11` — 3 figure вместо 1. Нужен фильтр длины caption.

#### Issue 19: Figure caption содержит текст страницы

#### Issue 16, 18: закрыты в `3ea85d8`

### Категория 2: Formula detection (формулы)

#### Issue 10 (средний): Bbox формул режет длинные дроби

Формулы `M = Φ/Φ`, `q = 37,5 i`, `c_τ = ds_τ/ds` — bbox не расширяется вправо на фрагменты.

**Фикс:** расширять bbox до ближайшего текстового span'а или конца ink-блока.

#### Issue 12 (высокий): merge_formula_spans склеивает короткие текстовые фрагменты

`f. g.`, `a. b.`, `h. i.` — короткие текстовые фрагменты воспринимаются как псевдо-формулы.

**Статистика weekend run:** formulas=2404, ok=1235 (51%), sem=603 (25%). То есть **половина формул плохие** — большая часть это merge-склейки.

**Фикс:** требовать, чтобы merged span содержал хотя бы один «формульный» символ (`=`, `+`, `−`, `∫`, `∑`, греческие буквы). Чисто текстовые склейки отсеивать.

#### Issue 13 (низкий): Горизонтальные линии как формулы

`text=_____`, `latex='-'` на icao_annex6 p200/300.

**Фикс:** фильтр по `text` — если строка только из `_`, `-`, `=`, `.` — не формула.

#### Issue 14 (низкий): CLI-сводка run_regions неполная

- Нет `susp` в сводке.
- Ошибка подсчёта `formula_ok`.

При перезапуске обрабатывает всё заново. `run_extract_pages --resume` есть, а в `run_regions` — нет.

**Фикс:** добавить `--resume` по аналогии.

#### `run_regions` перезаписывает существующий JSON

Нет режима `--merge` / `--append`. При обработке части PDF предыдущие страницы теряются.

**Фикс:** читать существующий JSON, добавлять, писать обратно.

#### PowerShell 5 проблемы

- `<` redirect не работает.
- `Tee-Object -Encoding utf8` не работает.
- `Set-ExecutionPolicy -Scope Process` блокируется Group Policy.
- Pipe между двумя `& $PythonMain` теряет stdout.

**Обход:** вызывать python по полному пути `$Root\.venv\Scripts\python.exe`, не активировать venv; использовать `ForEach-Object { $_ | Out-String | Add-Content ... }` вместо `Tee-Object`.

## Что можно улучшить в архитектуре

### 1. Оценка качества моделей на расширенном golden

Текущий golden v2 — 41 страница, 29 фигур. Для статистически значимой оценки нужно **100-150 страниц из 5-7 разных PDF**. Это ~4-6 часов работы.

**Что даст:** метрики с точностью ±3% вместо ±10%.

### 2. Переход на PP-DocLayout

Docling layout (RT-DETR) даёт AP≈71-77 на DocLayNet. **PP-DocLayout** даёт mAP@0.5 до 90.4% и работает в 100+ страниц/сек на CPU.

**Что даст:** если фильтры Docling не вытянут rdk89 до P=0.7 — переход на PP-DocLayout решит проблему.

**Цена:** ~200 MB зависимостей + время на интеграцию.

### 3. Использовать Docling picture classifier

Docling имеет встроенный `DocumentFigureClassifier`, который автоматически определяет тип фигуры (chart, diagram, photo, logo, signature). Это заменит ручной размет `kind` в golden.

**Что даст:** автоматическая классификация для RAG (по типам figure разная индексация).

### 4. Батчинг и параллелизация

Сейчас `run_regions` обрабатывает PDF последовательно. Можно запускать **N процессов параллельно** на N PDF (2-4 на 16 GB RAM). Это ускорит прогон в 2-3 раза.

**Что даст:** 25 часов → 8-10 часов.

### 5. Кэширование результатов между прогонами

Если PDF не менялся, не пересчитывать. Хэшировать `mtime + size` PDF и хранить mapping. Сейчас `--resume` в `run_extract_pages` уже есть, но в `run_regions` — нет.

## Что НЕ стоит делать

- **Не тюнить эвристики** (`detect_caption_figure_regions`, `detect_figure_regions`, `tighten_bbox_to_ink`). На golden v2 они дают P=0.28 — переобучены. Docling показал, что ML-модель работает в разы лучше.
- **Не расширять golden до всего корпуса.** 100-150 страниц достаточно для оценки. Полный golden на 6694 страницы — это недели ручной работы без практической пользы.
- **Не менять существующий `figures_v1.json`** — это regression baseline. Если нужно, создать новый `figures_v3.json`.
