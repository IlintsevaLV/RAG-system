## Три бага, требующих фиксов в коде

### Баг A (критический): FileNotFoundError при сохранении crop figure для doc_id с пробелом в конце

**PDF:** `ФАП 273 правила допуска к эксплуатации .pdf` (пробел перед `.pdf`)
**Ошибка:**
```
FileNotFoundError: [Errno 2] No such file or directory: 
'data\\cache\\figures\\ФАП 273 правила допуска к эксплуатации \\p0001_figure_00.png'
```

**Причина:** `doc_id = path.stem` не обрезает trailing whitespace. На файле `...эксплуатации .pdf` получается `doc_id = '...эксплуатации '` с пробелом в конце. При создании папки кэша для crop файла происходит:
- либо `Path.mkdir()` вызывается не для всех уровней,
- либо на Windows trailing space в пути отбрасывается/вызывает сбой.

**Фикс:**
1. В `run_regions.py` / `process_regions.py`: `doc_id = path.stem.strip()` — обрезать пробелы.
2. В функции сохранения crop: `out_path.parent.mkdir(parents=True, exist_ok=True)` перед `cv2.imwrite`/`PIL.save` — гарантировать существование родительской папки.

**Проверка:** прогнать `ФАП 273 правила допуска к эксплуатации .pdf` заново. Должен обработаться без переименования файла.

### Баг B (средний): Access Violation на больших PDF

**PDF:** `АС 1.1.S1000DR_2014.pdf` — **4046 страниц** (самый большой в корпусе)
**Ошибка:** `exit=-1073741819` = `0xC0000005` (Access Violation) через **6:11 часов**.

**Причина:** нехватка RAM. Всего 16 GB, свободно 5.4 GB. Docling layout + PyMuPDF rendering страниц не освобождают память между страницами, на длинных PDF происходит переполнение.

**Фикс (нужна автоматизация, ручной запуск по частям не подходит):**

1. **Разбиение на батчи внутри `process_pdf_regions`.** Обрабатывать страницы порциями по N (например, 200-500), после каждой порции:
   - сохранять промежуточный результат в целевой JSON (merge с предыдущим),
   - вызывать `del` для тяжёлых объектов (image_bgr, docling result),
   - вызывать `gc.collect()`.
2. **Merge результатов.** Так как `run_regions` перезаписывает `*_regions.json`, нужен режим `--append` или `--merge`: читать существующий JSON, добавлять новые страницы, писать обратно.
3. **Fallback на per-page режим при memory pressure.** Если `psutil.virtual_memory().available < 1 GB` — сохранять прогресс и перезапускать процесс с `--resume`-логикой.

**Проверка:** прогнать `АС 1.1.S1000DR_2014.pdf` без ручного разбиения — должен успешно обработать все 4046 страниц.

### Баг C (низкий): UnicodeEncodeError в stdout

**Ошибка:**
```
UnicodeEncodeError: 'charmap' codec can't encode character '\u2076' in position 89:
character maps to <undefined>
```

**Причина:** при печати в Windows console с кодировкой cp1251 символы типа `⁶` (superscript 6) не поддерживаются.

**Фикс:** принудительно utf-8 stdout в `run_regions.py` и `run_extract_pages.py`:
```python
import sys
if sys.stdout.encoding.lower() != "utf-8":
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
if sys.stderr.encoding.lower() != "utf-8":
    sys.stderr.reconfigure(encoding="utf-8", errors="replace")
```

Или обернуть принты в try/except с fallback на ASCII.
