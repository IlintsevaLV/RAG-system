# Golden-set для детекции рисунков

Нужен, чтобы мерить **полноту / точность / IoU рамки**, а не «кажется, что лучше».
Черновик: `data/ir/gold/figures_v1.json`. Поля `needs_review: true` — ещё не
подтверждены глазами (в этом клоне нет PDF).

## Что лучше: собрать вам или сгенерировать здесь

**Лучше вместе.** Скрипт и формат я уже положила. Автоматически «проанализировать
PDF и объявить золото» нельзя: детектор сам себе метки составит и мы начнём
оптимизировать ошибку. Нормальный цикл:

1. Я предлагаю страницы (уже в JSON) и грубые bbox из старых прогонов.
2. Вы на рабочем ПК открываете страницу, правите рамку (или ставите `figures: []`).
3. Снимаете `needs_review`.
4. Гоняете `python scripts/check_figure_detect.py --pdf data/raw/_1954.pdf`.

30–50 страниц достаточно. Не размечайте весь rdk89.

## Что должно быть в одной записи

| Поле | Зачем |
|---|---|
| `doc_id` + путь PDF | тот же id, что в IR |
| `page` | номер как в пайплайне (1-based) |
| `page_w`, `page_h` | из `page.rect`, чтобы сверять % площади |
| `figures[]` | **все** настоящие рисунки на странице; пустой список = негатив |
| `bbox` | PDF points, origin **top-left**, как в IR |
| `caption` | текст подписи, если есть (`Фиг. I.1. …`) |
| `kind` | `scheme` / `chart` / `photo` / `drawing` (грубо) |

Не включать: формулу, таблицу, колонтитул, всю страницу скана, декоративную рамку.

## Какие страницы набрать (приоритет)

**Негативы** (figure быть не должно) — иначе снова ползёт full-page:

- `_1954`: 1 (титул), 8 (оглавление), плотный текст без рисунка
- rdk89: 1, 9, 10, 25, 26, 39 (были ложные 98–100% страницы)
- любой двухколоночный текст без схемы

**Позитивы** — разные типы, по 2–4 на документ:

- `_1954`: 11 (фото/схема + «Фиг. I.1»), 20, 25 (подпись под рисунком)
- KT-160G: страница с графиком и осями; страница со схемой
- rdk89: 2–3 реальные схемы **не** на всю страницу
- usarmy: встроенные image XObject (там детектор `pdf_image` должен сработать)

Итого ориентир: ~15 негативов + ~20–25 позитивов.

## Как править рамку

Достаточно на глаз ±10 pt. IoU ≥ 0.5 считаем попаданием, ≥ 0.75 — хорошая рамка.
Если рисунков два — два объекта, не один общий bbox.

После правок: `"needs_review": false`.
